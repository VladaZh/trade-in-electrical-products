| | |
|---|---|
| Язык | **Python 3.12** |
| Зависимости | внешних библиотек нет, проект описан в `pyproject.toml` |
| Стиль | процедурный: только функции и `dict`, `list`, `tuple`; своих классов нет |

| Запуск | `python -m main <роль>`, роли: `client`, `sales`, `warehouse`, `delivery`, `reset` |

## Идея

Процесс содержит дорожки: **клиент, отдел продаж, склад, отдел доставки** и
**информационная система**. Программа повторяет это буквально:

- у каждой дорожки своя **консоль** (отдельный процесс, отдельный терминал);
- **решения участников принимают люди** в своих консолях;
- **шаги информационной системы выполняются автоматически**: проверка остатков, передача
  информации между отделами, уведомление клиента, отбор товара, списание остатков;
- заказ «переходит» из консоли в консоль по статусам: когда участник закончил свою часть,
  заказ сразу попадает в очередь следующего.

Консоли не обновляются сами. Чтобы увидеть новые задачи и сообщения, нажмите **Enter**.

## Запуск

Все команды выполняются из папки `src/`. Нужны **четыре терминала**, по одному на роль.

### Python / Poetry
```bash
poetry install                       # утсановка зависимостей
poetry run python -m main client     # консоль клиента
poetry run python -m main sales      # консоль отдела продаж
poetry run python -m main warehouse  # консоль склада
poetry run python -m main delivery   # консоль отдела доставки
poetry run python -m main reset      # возвращает систему в исходное состояние
```
Без Poetry при установленном Python 3.12 можно писать `python -m main <роль>`,
так как сторонних зависимостей у проекта нет.
Запуск без роли выводит справку.

### Управление в консоли
Консоль показывает задачи, ожидающие решения роли. Введите **номер задачи**, чтобы выполнить
её; **Enter** обновляет список; **0** - выход. Дополнительные команды:

| Консоль | Команды                                                     |
|---|-------------------------------------------------------------|
| Клиент | `n` - новый заказ, `o` (английская o) - мои заказы подробно |
| Отдел продаж | `o` (английская o) - все заказы                             |
| Склад | `s` - остатки по партиям, `o` (английская o) - все заказы   |
| Отдел доставки | `o` (английская o) - все заказы                                           |

Отвечать на вопросы программы можно любым удобным способом (настроено в console.py):
YES_WORDS = ("да", "д", "y", "yes")
NO_WORDS = ("нет", "н", "n", "no")

## Пример работы: самовывоз (ввод и ожидаемый вывод)

**1. Клиент** (`client`, выбрать клиента `1`):
```
Выбор: n
Товар> 101 25
Товар>                          (пустая строка - конец списка)
Выберите способ (1-2): 1        (самовывоз)
Отправить заказ? (да/нет): да
```
Ожидаемый вывод:
```
Сформирован заказ №1, сумма 237,500.00 руб.
Информация по заказу №1 передана в отдел продаж
```

**2. Отдел продаж** (`sales`): Enter, задача `1`, на вопрос «Данные заказа корректны?» - `да`.
```
Корректность данных подтверждена
Информация отправлена на склад отделом продаж
```

**3. Склад** (`warehouse`): Enter, задача `1` «Сформировать партию», `да`.
```
Сформирована партия: 2 строк отбора
  партия 1, ячейка A-01: Кабель ВВГнг 3x2.5 (бухта 100 м) - 20 шт.
  партия 2, ячейка A-02: Кабель ВВГнг 3x2.5 (бухта 100 м) - 5 шт.
```
Затем задача «Оформить документы на отгрузку», `да`:
```
Склад оформил документы на отгрузку №1
Заказ №1 готов на складе
Клиенту «ООО «ЭлектроМонтаж»» отправлено сообщение о готовности заказа №1
```

**4. Клиент**: Enter. Появляется сообщение системы:
```
    Заказ №1 собран и готов к выдаче на складе. Срок хранения - 5 дн. Приходите за заказом.
```

**5. Склад**: Enter, задача «Самовывоз: срок хранения, выдача заказа»: «Срок хранения заказа
вышел?» - `нет`, «Клиент пришёл?» - `да`.
```
Заказ выдан клиенту со склада
Заказ завершён
Складские остатки обновлены
```
Итог: статус «заказ получен», остаток партии 1 равен 0, партии 2 равен 10.

### Другие ветки процесса

| Ветка | Как получить | Результат |
|---|---|---|
| Не хватает товара | клиент заказывает `101 50` | «Заказ клиента ... отклонён», «Доступно максимум: ... - 35 шт.», «Создание заказа отменено» |
| Уточнение данных | клиент 2 заказывает доставку (адреса нет); продажи отвечают `нет` и пишут запрос; клиент вводит адрес | заказ возвращается в отдел продаж |
| Доставка, клиент принял | после склада клиент вводит дату; доставка: «Загрузить товар», «Доставить товар»; клиент `да`; доставка: «Зафиксировать факт доставки» | статус «заказ выполнен», остатки списаны |
| Доставка, клиент отказался | клиент отвечает `нет`; доставка: «Отменить заказ», «Вернуть товар на склад» | статус «заказ отменён», остатки не меняются |
| Срок хранения вышел | склад отвечает `да` на «Срок хранения заказа вышел?», затем «Расформировать заказ» | статус «заказ не получен» |


**Сообщения клиенту** показываются в его консоли при следующем нажатии Enter, каждое один раз.
**Резервирование:** при формировании партии товар резервируется под заказ (колонка «В резерве»
по команде `s`), поэтому другой заказ его не займёт. Резерв снимается при списании, отмене или
расформировании.

## Допущения и ограничения

- Состояние хранится в файле, поэтому все консоли запускаются на одном компьютере, их
работа синхронизирована.
- Консоли обновляются **вручную по Enter**.
- Запись в файл защищена блокировкой (`storage.py`): консоли не портят данные друг другу.
  Зависшая блокировка снимается через 5 секунд.
- Продавец может запрашивать уточнения у клиента сколько угодно раз.
- Дата доставки не может быть раньше сегодняшней; перед загрузкой товара отдел доставки сам
  решает, наступила ли дата.
- Решение «Клиент пришёл?» принимает склад, как показано на диаграмме.
